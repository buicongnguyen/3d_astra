# A7 — Large battles

## Simulation

Seven interleaved runs after two warm-ups per tree, with GC between runs. Each run orders 300 troops across the Riverlands bridges and plays 120 fixed ticks.

| Metric | bc72711 | A7 | Change |
|---|---:|---:|---:|
| Mean tick | 2.269 ms | 1.468 ms | −35.3% |
| p95 tick | 5.954 ms | 3.112 ms | −47.7% |
| Final state hash | 102fa326 | 102fa326 | identical |

The older 300-second, three-rival scenario is a lighter workload. Its preliminary A/B comparison gave 0.216 → 0.210 ms mean and matching hash `9e088b28`. The speedup depends on the number of movement orders.

Only failed paths and directional A* edge results are cached, keyed by radius and ordinary/slim clearance. A rebuild invalidates them, including bridge changes and snapshot restore. The endpoint check against exact world coordinates still runs for successful paths. Regression coverage compares the complete routes with caching disabled in both directions with an open, blocked and reopened crossing.

## Rendering and phone frames

| Eco scenario | Draws before | Draws after |

| Selected phone dock | 171 | 92 |

All 34 release render-budget scenarios passed, including the zero-upload assertions on stationary frames. The four scenarios above have tighter draw limits. The two Defence cases entered Round A above their original limits. Rings and bars now use two instanced batches with per-instance state, ground footprints share one disc, and a rigid group can draw its matte and metallic finishes together. Reflective parts retain their per-finish lighting.

The separate live phone probe starts with 314 units, 150 selected, on a 390×844 Eco viewport. Chrome used a 4× CPU throttle and D3D11 on an RTX 4080 SUPER. Across 54 active-frame intervals, median frame time went from 83.2 to 16.8 ms and p95 from 367.3 to 50.1 ms. The baseline ended the sample with 264 units and A7 with 314 because the same number of browser frames covered different amounts of game time. The fixed-tick headless A/B above measures equal game time. An earlier busy-machine pass measured 116.7 ms p95 on A7; timing varies with host load. These are emulated CPU measurements. Hardware confirmation belongs to the owner phone round.

## Verification

The full unit run had 1,092 passes, 28 skips and zero failures. All 99 full golden checks passed, including the idle fingerprint `d071360b`. The original mission checksums passed and all eight full balance baselines were identical. Files in [a7/](a7/) include both phone images, per-run metrics and the interleaved tick report.

Reproduce the measurements from `github-io` using the desired builds on port 4243.

```powershell
node --expose-gc tools/perf-ab.mjs --a bc72711 --b src --scene riverlands-army-300 --runs 7 --warmup 2
$env:TEST_URL='http://127.0.0.1:4243/'
node tools/perf-phone.mjs .tmp/a7-recheck after
npm run test:render-budget
```
