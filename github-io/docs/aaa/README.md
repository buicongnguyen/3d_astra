# AAA implementation plan: how to use it

This folder turns [../AAA_PLAN_2026-11.md](../AAA_PLAN_2026-11.md) (the evaluation and the six stages) into work packages an implementing agent can pick up one at a time. It was written at version 0.9.4, commit `da80394`.

| File | Stage | Size |
|---|---|---|
| [STAGE_1_FEEL.md](STAGE_1_FEEL.md) | Combat feel, campaign difficulty, AI retune | 4 packages |
| [STAGE_2_FACTIONS.md](STAGE_2_FACTIONS.md) | Faction rosters, traits, AI personalities, per-match model loading | 7 packages |
| [STAGE_3_BATTLEFIELD.md](STAGE_3_BATTLEFIELD.md) | Height, cover, weather, optional air units | 5 packages |
| [STAGE_4_STORY.md](STAGE_4_STORY.md) | Staged scenes, voice tones, decisions, veterans, campaign map, endings | 6 packages |
| [STAGE_5_REPLAY.md](STAGE_5_REPLAY.md) | Achievements, challenges, skirmish options, replay viewer | 4 packages |
| [STAGE_6_SHIP.md](STAGE_6_SHIP.md) | Phone round, install, multiplayer hand-over | 3 packages |

**How to hand it over.** Give the agent this file and one stage file, and name the package: "Implement package 2.1 from docs/aaa/STAGE_2_FACTIONS.md, following docs/aaa/README.md." Packages inside a stage are in dependency order. Stages 1, 2 and 3 must be done in order; 4 can start after 1; 5 needs 2; 6 is last.

## The project in one page

- Repository `3d_astra`; the game is in `github-io/` (Three.js r185, Vite, plain JavaScript modules, no framework). Run every command from `github-io/`.
- A push to `main` runs CI (`.github/workflows/pages.yml`: unit tests, build, browser suites in groups) and deploys `dist/` to GitHub Pages only when everything passes. The owner tests on the live site.
- Read first: `docs/ARCHITECTURE.md` (module map), `docs/TESTING.md`, `docs/MISSIONS.md` (mission format), `docs/ASSET_PIPELINE.md` (model contract), `docs/WORLD.md` (story bible), `docs/BALANCE.md`.
- Rules: `src/simulation.js` plus mixins in `src/sim/*.js`. Numbers: `src/balance.json` (`definitions.<type>`). AI speeds: `AI_SPEEDS` in `src/ai-plan.js`. Maps: `src/maps.json` and `src/terrain.js`. Missions: `src/story/missions.js`. Factions and cast: `src/story/world.js`.
- Client: `src/main.js` composes `src/app/*.js` modules that share state `S` and a function bus `A`; rendering is `src/view.js` with `src/fx.js` (effects) and `src/entity-batches.js` (instanced batches).

## Rules every package must follow

**Simulation**
1. The simulation is deterministic: no `Math.random`, no `Date`, no reading the client. `tests/` has replay and hash checks that will fail otherwise. **The simulation has no random numbers at all today.** The first package that needs chance (3.3, changing weather) adds one generator, `sim.rng` (a small integer PRNG such as mulberry32, seeded from a new `seed` option with a fixed default, its state saved in the snapshot); everything else stays chance-free. Cosmetic randomness in the view already has its own seeded generator and must never touch the simulation.
2. Every player action goes through `sim.command({ team, type, ... })` in `src/commands.js`. Add a command for any new action; never mutate the simulation from `src/app/`.
3. New state on `sim`, `sim.players[]` or entities must survive `sim.serialize()` and `Simulation.load()`, and an old save without the field must still load (treat a missing field as its default).
4. All numbers go in `balance.json` or a data file, not in code.

**Text**
5. Every visible English string needs a Vietnamese entry in the same change: interface text in `src/locales/vi.json`, story text in `src/locales/story-vi.json`. `npm test` fails until both are complete. Use static string literals; sentences with numbers or names need a `patterns` entry (see `docs/ARCHITECTURE.md`, "Text and translation").

**Interface**
6. Every screen works at 1440x900, 390x844 and 844x390. No text under 11 px, no touch target under 44 px, no sideways scroll. `tests/layout-f.mjs` and `tests/ui-quality.mjs` show how to assert this.
7. Phone and PC are both first-class: every new action needs a touch control and, on PC, a key listed in `src/hotkeys.json` and `docs/PC_SHORTCUTS.md`.
8. Respect the reduced-motion setting and Eco quality: screen shake, hit-stop and decorative particles are off or reduced there.

**Performance**
9. Phone frame time must not get worse. Before and after any visual change, run `npm run test:render-budget` and record draw calls, triangles and frame time at 390x844 in the changelog entry. New repeated objects must be instanced (`src/entity-batches.js`) and must not cast shadows unless a building.
10. Materials and shader programs must outlive a match restart (see `docs/ARCHITECTURE.md`, last section).

**Art**
11. All art is original and generated by the Blender scripts in `tools/blender/` (Blender 4.5 LTS, headless). No downloaded models, textures, fonts or sounds. Follow the runtime contract in `docs/ASSET_PIPELINE.md`: every mesh carries `POSITION`, `NORMAL`, `TEXCOORD_0`, `COLOR_0`; `Team*` materials are recoloured; infantry keep `leg_L`/`leg_R`.
12. Do not compress models with gltfpack quantisation: it was tried in 0.9.4 and the batched renderer drew them distorted.

**Tests and delivery**
13. A package is done only when: `npm test` passes; `npm run check:missions` passes if rules, balance or missions changed; the browser suites named in the package pass locally against a built preview (`npx vite build`, `npx vite preview --host 127.0.0.1 --port <free port> --strictPort`, `TEST_URL=http://127.0.0.1:<port>/ npm run test:<name>`); and CI is green after the push.
14. New browser suites use `tests/lib/harness.mjs` and must be added to a group in `.github/workflows/pages.yml` and to `package.json` scripts. CI renders in software and is slow: never assert on wall-clock timing; dispatch input inside the page and poll state instead of sleeping (see the notes at the top of `tests/ui-extras.mjs`).
15. Each package ends with a `docs/CHANGELOG.md` entry, a version bump in `package.json`, and updates to any doc whose facts changed (`ROADMAP.md`, `BALANCE.md`, `MISSIONS.md`, `WORLD.md`, `TESTING.md`).
16. Report honestly: list what was not tested or not verified. Do not weaken a test to make it pass; if a test is wrong, say why in the commit.

**Housekeeping**
17. Do not touch the Godot twin (`3d_astra_godot`); it is frozen. Do not commit the untracked `share-images/` folder. Stage files explicitly.
18. Many source files use CRLF line endings; keep each file's existing endings.
19. Other projects run servers on this machine: use a free port, never 4173, 4197 or 5178, and stop only the process you started (by PID).
20. Known pitfall: eleven browser suites wait for `view.models.size === 13`. Package 2.0 replaces that with a ready flag; until then, adding a model breaks them.

## Decisions taken as defaults

The owner has not answered these yet; the plan assumes the first option. Each is isolated to the package named, so changing one later is cheap.

|---|---|---|

## Things only the owner can do

- Play missions 1 to 4 and one Normal skirmish on a PC and a real phone with sound on, and write down what felt wrong. Stage 1 uses these notes; without them, package 1.1 follows the defaults written there.
- Listen to the music and effects. No test covers taste.
- Approve the look of each new faction from the review sheets (package 2.2) before the models are wired in.
