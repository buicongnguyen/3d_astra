# Blender asset pipeline

All 13 unit and structure models and the scenery set (boulders, crystal deposits, trees, bushes, reeds, crates and truss bridges) are generated by Python in Blender 4.5 LTS. There are no external models, textures or paid services. The committed GLBs in `public/models/` are all the game needs; Blender is only required to change the art.

| File | Role |
|---|---|
| `tools/blender/frontier_kit.py` | Shared toolkit: bevelled hard-surface primitives, materials, baked lighting, export |
| `tools/blender/generate_assets.py` | Units and structures → `public/models/<type>.glb`, `manifest.json` |
| `tools/blender/generate_environment.py` | Scenery → `public/models/environment.glb`, `environment-manifest.json` |
| `tools/blender/animate_units.py` | Bakes the rigid-part clips used by the Godot edition into the unit GLBs |
| `tools/blender/preview_assets.py` | Renders review sheets of the exported GLBs (in-game camera or close-up) |
| `tests/assets.test.js` | Checks the runtime contract below on every committed GLB |

## Look development

- **Hard-surface geometry.** Plates are bevelled (two segments on major parts, chamfers on small ones). A weighted-normal modifier keeps large faces flat while the bevels catch light, so silhouettes read at RTS camera distance.
- **Baked lighting in `COLOR_0`.** Each vertex stores ray-traced ambient occlusion against the whole model and a ground plane, brighter worn edges on bevels, grime near the ground, and soft mottling. Two details matter:
  - Rays that hit a back face start inside another part. They are ignored, so buried vertices cannot darken the faces they share.
  - Aim/recoil parts (barrels, the tower head) do not occlude the body, because they move at runtime.
- **Grey vertex colour.** The colour is kept grey so the runtime recolouring of `Team*` materials multiplies cleanly.
- **PBR materials.** Materials only describe the surface: painted armour, bare steel, rubber, glass, emissive lights, crystals. The renderer adds a PMREM room environment to these materials (not to the terrain) so metals reflect.
- **Coarse lattice for structures.** Structures are sliced on a coarse grid so long walls and roofs carry AO gradients. Units are not sliced, to keep their triangle count down.

## Runtime contract (`src/view.js`, `src/environment-view.js`)

- Blender −Y is the front, +Z is up, units are metres and the origin is at ground level. Health bars sit at 2.9 (units) and 5.2 (structures).
- Every mesh in a GLB has the same attributes (`POSITION`, `NORMAL`, `TEXCOORD_0`, `COLOR_0`). The view merges meshes by material, and `mergeGeometries` silently drops a bucket whose attributes differ.
- Materials named `Team*` are recoloured per faction; `TeamGlow*` also gets the team's emissive colour.
- Infantry keep `leg_L`/`leg_R` empties at the hips; the renderer swings them and `animate_units.py` bakes clips from them.
- Meshes named `Main_cannon`, `Muzzle_brake`, `Barrel*`, `Cannon*`, `Muzzle*` or `Turret_head*` form the aim/recoil rig (`RIG_PART`).
  - GLTFLoader turns Blender's `Barrel.001` into `Barrel001`, and the pattern accepts that.
  - The tower's whole head turns with its barrels.
- Muzzle positions match the `weapons` heights and reaches in `src/visual-style.json`, so tracers leave the barrels.
- Scenery roots are named `asset_<name>`. `asset_rock_*` boulders are instanced on every map's rock obstacles and tinted with the map's rock colour. `asset_crystal_alloy`/`asset_crystal_energy` are cloned for each deposit.

## Regenerating

Headless (reproducible; also rewrites the `.blend` libraries in `assets/source/`):

```sh
blender --background --python tools/blender/generate_assets.py
blender --background --python tools/blender/generate_environment.py
blender --background --python tools/blender/animate_units.py
```

Live through MCP for Blender (`.mcp.json` in the sibling `3D_claudeopus55` repository). Execute this in the connected Blender:

```python
import sys; sys.path.insert(0, r'<repo>/github-io/tools/blender')
import generate_assets, generate_environment
generate_assets.build_all(export=True)
generate_environment.build_environment(export=True)
```

The live path builds into a separate `Frontier` scene. It never switches the window's scene, which crashed Blender 4.5 when done from an MCP call. It exports each asset by collection, linking that collection into the open scene only for the duration of the export. Run `animate_units.py` headless afterwards: it deletes scene objects and saves `.blend` files, so it must not run in an interactive session.

Review sheets of the exported files:

```sh
blender --background --python tools/blender/preview_assets.py -- out.png game hq barracks foundry relay tower
blender --background --python tools/blender/preview_assets.py -- out.png hero worker ranger vanguard
```

Then run `npm test`, which includes `tests/assets.test.js`, and the browser suites.

## Known limits

- Vertex-colour AO is limited by vertex density. Very large, unsliced faces show only corner-to-corner gradients.
- Units are posed rigid parts; only the legs animate in the browser.
- There are no texture maps: micro-detail such as panel lines, decals and scratches would need baked normal/roughness textures. That is the main remaining step toward a hand-authored finish.
- Each unit draws as roughly 10–14 meshes (one per material, plus legs and rig), without GPU instancing. Very large armies are draw-call bound before they are triangle bound.
