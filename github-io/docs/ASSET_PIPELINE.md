# Blender asset pipeline

The 13 base unit and structure models, 12 faction model candidates and the scenery set (boulders, crystal deposits, trees, bushes, reeds, crates and truss bridges) are generated by Python in Blender 4.5 LTS. There are no external models, textures or paid services. The committed GLBs in `public/models/` are all the game needs; Blender is only required to change the art.

| File | Role |
|---|---|
| `tools/blender/frontier_kit.py` | Shared toolkit: bevelled hard-surface primitives, materials, baked lighting, export |
| `tools/blender/generate_assets.py` | Units and structures → `public/models/<type>.glb`, `manifest.json` |
| `tools/blender/generate_environment.py` | Scenery → `public/models/environment.glb`, `environment-manifest.json` |
| `tools/blender/animate_units.py` | Bakes the rigid-part clips used by the Godot edition into the unit GLBs |
| `tools/blender/preview_assets.py` | Renders review sheets of the exported GLBs (in-game camera or close-up) |
| `tests/assets.test.js` | Checks the runtime contract below on every committed GLB |

## Look development

- **Hard-surface geometry.** Plates are bevelled (two segments on major parts, chamfers on small ones). A weighted-normal modifier keeps large faces flat while the bevels catch light, so silhouettes read at RTS camera distance.
- **Baked lighting in `COLOR_0`.** Each vertex stores ray-traced ambient occlusion against the whole model and a ground plane, brighter worn edges on bevels, grime near the ground, and soft mottling. Two details matter:
  - Rays that hit a back face start inside another part. They are ignored, so buried vertices cannot darken the faces they share.
  - Aim/recoil parts (barrels, the tower head) do not occlude the body, because they move at runtime.
- **Grey vertex colour.** The colour is kept grey so the runtime recolouring of `Team*` materials multiplies cleanly.
- **PBR materials.** Materials only describe the surface: painted armour, bare steel, rubber, glass, emissive lights, crystals. In High quality the renderer adds a PMREM room environment to metallic, glass and crystal materials so they reflect. Matte paint, fabric, scenery and terrain do not get it, and Eco quality skips it entirely, because the lookup is the most expensive part of the model shaders on weak GPUs.
- **Optional lattice slicing.** `Asset(lattice=…)` can slice large faces so they carry AO gradients. No shipped asset uses it: at game zoom it tripled wall geometry for little visible gain.

| Group | Budget |
|---|---|
| Infantry | 2.8–3.2k |

The manifests record exact counts. Budgets are set by the CI browser tests, which render with SwiftShader, a CPU software renderer. A frame of the start scene must stay near the previous release (about 160–250 ms there, versus about 520 ms before the budgets were trimmed).

## Runtime contract (`src/view.js`, `src/environment-view.js`)

- Blender −Y is the front, +Z is up, units are metres and the origin is at ground level. Health bars sit at 2.9 (units) and 5.2 (structures).
- Every mesh in a GLB has the same attributes (`POSITION`, `NORMAL`, `TEXCOORD_0`, `COLOR_0`). The view merges meshes by material, and `mergeGeometries` silently drops a bucket whose attributes differ.
- Materials named `Team*` are recoloured per faction; `TeamGlow*` also gets the team's emissive colour.
- Infantry keep `leg_L`/`leg_R` empties at the hips; the renderer swings them and `animate_units.py` bakes clips from them.
- Meshes named `Main_cannon`, `Muzzle_brake`, `Barrel*`, `Cannon*`, `Muzzle*` or `Turret_head*` form the aim/recoil rig (`RIG_PART`).
  - GLTFLoader turns Blender's `Barrel.001` into `Barrel001`, and the pattern accepts that.
  - The tower's whole head turns with its barrels.
- Muzzle positions match the `weapons` heights and reaches in `src/visual-style.json`, so tracers leave the barrels.
- Scenery roots are named `asset_<name>`. `asset_rock_*` boulders are instanced on every map's rock obstacles and tinted with the map's rock colour. `asset_crystal_alloy`/`asset_crystal_energy` are cloned for each deposit.

## Regenerating

Headless (reproducible; also rewrites the `.blend` libraries in `assets/source/`):

```sh
blender --background --python tools/blender/generate_assets.py
blender --background --python tools/blender/generate_environment.py
blender --background --python tools/blender/animate_units.py
```

Live through MCP for Blender (`.mcp.json` in the sibling `3D_claudeopus55` repository). Execute this in the connected Blender:

```python
import sys; sys.path.insert(0, r'<repo>/github-io/tools/blender')
import generate_assets, generate_environment
generate_assets.build_all(export=True)
generate_environment.build_environment(export=True)
```

The live path builds into a separate `Frontier` scene. It never switches the window's scene, which crashed Blender 4.5 when done from an MCP call. It exports each asset by collection, linking that collection into the open scene only for the duration of the export. Run `animate_units.py` headless afterwards: it deletes scene objects and saves `.blend` files, so it must not run in an interactive session.

Review sheets of the exported files:

```sh
blender --background --python tools/blender/preview_assets.py -- out.png game hq barracks foundry relay tower
blender --background --python tools/blender/preview_assets.py -- out.png hero worker ranger vanguard
```

Then run `npm test`, which includes `tests/assets.test.js`, and the browser suites.

### Interface art

`render_ui_art.py` renders the start-screen key art, the emblem and the HUD portrait atlas from the exported GLBs, so the art always matches the models in play. Run it headless after the models change:

```sh
blender --background --factory-startup --python tools/blender/render_ui_art.py -- src/art
```

Arguments after the output folder (`keyart`, `portraits`, `emblem`) render only those parts. The portrait atlas is paired with a mask render in which team paint is white and everything else is held out. The page multiplies the player's army colour through that mask, so one atlas serves every colour choice. The atlas is 4 columns by 8 rows (768 by 1536 pixels): the original thirteen, the twelve approved faction portraits, then the four flyers of 0.18 (`kite`, `hawk`, `balloon`, `glider`; manifest entries marked `air: true`, written by `generate_air.py -- --manifest`). Portrait order is part of the page contract (`PORTRAIT_ORDER` in `src/portraits.js`). Buttons and labels are never baked into images. See [UI_REDESIGN.md](UI_REDESIGN.md).

**Story character portraits** (`public/portraits/<id>.webp`, loaded by `src/cast-portraits.js`) are painted 2D images since 2026-11-17, generated by Codex (built-in image generation) from the `portrait` text of each character in `CAST` (`src/story/world.js`), chosen by the owner and saved at 256 by 256 pixels (WebP quality 85, 3–14 KB). They replace the Blender busts of `tools/blender/render_cast_portraits.py`, which stays as a fallback way to make them; a missing file falls back to the inline SVG. Rules for new ones: one style for all (painted semi-realistic bust, dark teal #0c2029 backdrop, faction-colour glow and rim light), face 40–50% of the square, no text or border (the page draws the faction ring), and check it at 28 px as well as 160 px.

## Known limits

- Vertex-colour AO is limited by vertex density. Very large, unsliced faces show only corner-to-corner gradients.
- Units are posed rigid parts; only the legs animate in the browser.
- There are no texture maps: micro-detail such as panel lines, decals and scratches would need baked normal/roughness textures. That is the main remaining step toward a hand-authored finish.
- Each unit draws as roughly 10–14 meshes (one per material, plus legs and rig), without GPU instancing. Very large armies are draw-call bound before they are triangle bound.

## Faction candidates (package 2.2)

`generate_assets.py -- --factions` delegates to generate_factions.py and writes twelve candidate GLBs plus assets/source/frontier-factions.blend. All are built with frontier_kit; no external art is used. The manifest marks their faction, triangle limit and owner approval dated 2026-11-11. They are absent from runtime definitions and boot's core model set until the faction gameplay packages.

`preview_factions.py` renders all eight approval sheets through preview_assets.py. The latter accepts --team=RRGGBB and --greyscale, and fits the full projected geometry at the game camera angle. See [aaa/review/README.md](aaa/review/README.md).

The loader retains a `hover` marker as template metadata; only a marked unit receives the optional cosmetic bob. Base models keep their existing shadow behavior; new faction units use no shadow pass, and new buildings may cast shadows.

## Round 3 warm kit (R3-F)

- **Armour:** `Armor` is a glossy warm sand (roughness 0.25, low metal). Keep any new armour-like paint in the same bake class, so `src/view.js reflects()` holds: metalness ≥ 0.5 or roughness ≤ 0.25. That way no model gains a baked mesh, and so no draw.
- **Dark:** keep it for tracks, boots and joints (`Undercarriage`).
- **Role paints for the shared infantry:** `ArmorMedic`, `ArmorWorker`, `Cross`, `Cape`, `Safety`.
- **Faction paints (`a.armor` in `generate_factions.py`):** `ArmorAshfall`, `ArmorSunward`, `ArmorWardens`, `ArmorVeil`. They keep a faction's identity when the player picks another team colour. Team paint goes on bands, fins, shields and crests.
- **Lit windows:** use the emissive `Window` material. Night looks match the `Window*` name.
- **Partial rebuild:** `generate_factions.py -- <names>` rebuilds only those faction models. The Drone is skipped unless it is named.
- **Review sheets and luminance:** run `docs/aaa/results/round3/f/render/run.mjs` (see `docs/aaa/results/round3/f.md`).

Licence: owned by the project like the rest of its original art.
- **Changes here:** `layer-foreground-squad.webp` was resized to 1280×853 and re-encoded (WebP quality 72, alpha quality 75): 572,364 → 289,986 bytes. Every other file is byte-identical to the source.
- **Placement:** `src/app/cover-layers.js` carries the source's table (x, y, width per frame, back to front, motion amplitudes). `src/app/cover.js` fetches the layers only after the game's models are in, places them exactly over the flat cover and cross-fades.
- **Budgets:** one flat cover at first paint (≤ 350 KB each); layers ≤ 1.7 MB in total, lazy; checked by `tests/cover-ui.test.js`.
